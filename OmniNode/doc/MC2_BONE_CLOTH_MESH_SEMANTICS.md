# BoneCloth 的离散 MeshCloth 语义

## 设计结论

BoneCloth 不以复刻 MagicaCloth2 的骨链实现为目标。它在物理世界中的定义是：

> 一个骨骼代表一个离散物理粒子和一个可写回的局部区域；一组骨骼通过连接图组成一个简化的 MeshCloth。

因此，同一物理世界里的 MeshCloth 与 BoneCloth 应共享粒子属性、固定点、距离约束、tether、深度、碰撞和缓存语义。骨骼只是输入和输出载体，不是另一套物理规则。

## 数据边界

### 参与模拟的内容

- 最终 proxy 的粒子位置、属性、线、三角形和邻接图。
- Pin 只转换为粒子的 Fixed 属性；末端求解粒子继承对应末端骨骼的 Pin。
- 基线、图父级、tether 根和深度从最终 proxy 图构造，采用 MeshCloth 的图算法。
- 三角形是面约束的补充，不能替代结构边；所有 proxy 边都保留在 line 列表，三角形另外参与面邻接和弯曲/碰撞约束。

### 不参与模拟的内容

- Blender 骨骼的父子级不再决定模拟 parent、粒子深度、tether 根或姿态传播方向。
- Blender 父子级只用于：选取连续骨链、拒绝 `use_connect=True` 输入，以及把世界姿态反算成 PoseBone 的 `matrix_basis`。
- `root_rotation` 和 `rotational_interpolation` 不再是 BoneCloth 的用户参数。内部 ABI 暂时保留这两个槽位，但 BoneCloth 固定使用完整的图几何方向。

## 姿态与写回

1. 每个真实骨骼的头部位置直接取对应求解粒子的位置。
2. 骨骼方向从最终 proxy 图的实际子邻接粒子推导。固定子粒子也使用其实际位置，不能退回动画基线；这保证尾端固定时上一根骨骼仍会吸附正确方向。
3. 末端求解粒子只作为骨骼尾点和局部图节点存在，不写回 Blender；它仍参与距离、tether、碰撞和姿态推导。
4. 最终世界姿态一次性转换为 PoseBone 的局部矩阵。父子级只参与 Blender 的矩阵反算，不参与粒子姿态的二次传播。

## 拓扑和深度

BoneCloth 的连接模式表达的是离散表面：

- `Line`：只建立每条输入链的纵向连接。
- `Sequential`：建立相邻链的同深度横向连接。
- `SequentialLoop`：在首尾链之间增加同深度连接。

同深度由输入链的显式顺序定义，用于构造表面图；它不是 Blender 的全局骨骼深度。基线会在这张图上选择可复现的图父级，固定边界到移动粒子的最短图距离用于深度和 tether 根判定。

## 仍需验证的问题

- 多链长度不一致时，横向连接是否应按最近几何邻居补边，而不是只按同索引深度连接。
- 多个固定岛之间的 tether 是否需要按区域、距离或权重拆分，当前先使用 MeshCloth 的最近固定边界语义。
- 只有线拓扑时没有面法线，骨骼局部滚转仍需要明确的稳定参考轴；当前沿用骨骼静态局部 frame，并只从图位置更新方向。
- 运行中调试应直接显示 proxy 图、Fixed/Move、tether 根、图深度和写回姿态，不能显示 Blender 父子树推导结果冒充物理状态。

## 验收标准

- 改变 Blender 父子组织但保持最终 proxy 图不变，模拟结果不变；只有写回矩阵反算路径可以变化。
- 整体平移后，末端粒子与末端骨骼尾点保持一致，不出现尾端向上突出。
- 固定末端骨骼时，上一根骨骼的世界位置和方向都跟随求解图，而不是使用 `root_rotation` 的基线方向。
- 双端固定链的 tether 根、图深度和同深度横向粒子与对应 MeshCloth 图保持同一语义。
