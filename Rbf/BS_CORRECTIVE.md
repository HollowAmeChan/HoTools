# HoTools BS 修型（Blender 4.5 / HoFBX v3）

## 工作流

骨架对象的数据属性中，`HoTools 修型总览` 与 `HoTools辅助骨总览` 平级。N 面板的 RBF → 修型复用同一绘制函数，并可折叠。

三个原生 UIList 管理规则、修型姿势和影响物体。规则与姿势位于上方，影响物体属于当前规则。左侧竖排按钮管理列表；规则另有全部启用、全部禁用。下方带框区域只编辑当前规则。

1. 添加规则，指定参考骨骼，将需要修型的网格加入影响物体列表。
2. 摆出参考骨骼的局部旋转姿态，点击修型姿势列表的 `+`。它记录当前姿态并自动生成不重复的 `_BSC_poseN` 名称；每个姿势都作用于规则的全部影响物体。
3. 点击姿势行右侧的预览按钮，直接切到该姿态；基准行的按钮回到零旋转。姿势名称可以直接在列表行内编辑，角度只读显示。
4. 点击“重置规则”：按规则影响物体为每个姿势建立同名形态键，并生成驱动器。覆盖选项默认开启；关闭后复用已有形态键、保留雕刻数据。
5. 修改姿势名称、影响半径或影响物体后，点击“刷新驱动”更新已有键的驱动器；新增形态键或改变规则影响范围时使用“重置规则”。

基准姿势始终位于姿势列表首行，固定为零局部旋转，输出全零；不能编辑、移动、覆盖或删除。其他姿势各自对应一个 RBF 输出通道，在自己的控制点上输出 1，其他姿势和零点输出 0（含 1e-6 求解正则误差，输出截取到 0..1）。

“重置规则 / 刷新驱动 / 移除驱动 / 删除控件”正常处理活动规则，Shift 点击弹出“处理全部规则”复选框，确认后立即批量执行。“删除控件”删除姿势和本工具驱动器，保留已有形态键。新增姿势需要不同于已有姿势及零点的局部旋转。

## 驱动与资源

- 仅有 RBF 模式：Gaussian 核、单骨骼局部 XYZ 旋转，界面以度数只读显示，RNA/导出以弧度存储。轴角差按 ±π 环绕。这不是多骨骼或 SO(3) 距离求解器；XYZ 奇异姿态仍需按实际姿态采样验证。
- Blender 预览直接读主骨骼 `LOCAL_SPACE`，固定 `rotation_mode=XYZ`；不创建 ADIR、缓存骨或骨骼约束。
- 短表达式调用 `driver_namespace["hotools_bs_rbf"]`，系数存在控制器的 StringProperty。X 输入兼作 `hotoolsBscMarker` 所有权标记，只有三个变换变量，无下划线开头的变量名。
- 一次构造共享核矩阵，一次多右端求解所有姿势；求值时按规则和输入值缓存整组输出。小矩阵用纯 Python，大矩阵用 Blender 自带 NumPy，避免每个姿势重复 Gaussian 运算。
- 缓存不依赖帧号，同一帧内不同旋转立即重算。刷新替换编译数据并清缓存；加载、撤销、重做恢复已保存的编译数据；移除/清空和卸载释放对应缓存与处理器。
- 刷新及重置先预检整批规则；重复名称、重复点、无效引用、非相对形态键、重复输出和其他驱动器占用会被拒绝。移除根据骨架对象和规则所有权扫描，避免修改目标后遗留旧驱动器；保留其他工具驱动器。
- 工程重开需要 HoTools 已启用及 Blender 允许相应 Python 驱动。算法只由插件提供，不执行工程中任意保存的源代码。

## HoFBX / Unity

作者数据只保存规则影响物体和姿势；导出边界按“姿势 × 影响物体”临时生成 v3 的 `tasks[{id,bsName,pointId,targets}]`，因此 Unity 侧仍接收明确的输出目标。`rbf.controlPoints[{id,pose}]` 不包含基准点，基准固定 `includeBase=true, basePose=[0,0,0]`。Exporter 与控制器共用 schema/version 常量。

导出预处理仍只在需要清除源骨骼 rest 旋转时将测量骨映射为既有 MCH 骨，不创建 ADIR。Unity 中控导入将每个姿势目标展开成一条输出规则：所属点权重 1，其余点和零点为 0，保留姿势名称和源骨骼信息。来自同一元数据来源的规则可替换重导，手动规则保留。

## 验证

`tests/test_blender_bs_corrective.py` 覆盖原生列表数据操作、姿势名称与固定零点、重置覆盖开关、多网格、外部驱动保护、父级和骨架物体旋转隔离、短表达式、缓存复用/失效、保存重开、批量执行及资源释放。

`tests/benchmark_bs_corrective.py` 对比逐输出缓存与整规则缓存的实际依赖图更新。2026-11-18 本机 Blender 4.5.8，8 线程，5×60 次更新取轮均值中位数：

| 作者点 / 输出数 | 逐输出缓存 ms/update | 整规则缓存 ms/update |
|---|---:|---:|
| 3 / 12 | 0.361 | 0.329 |
| 12 / 48 | 1.004 | 0.933 |
| 24 / 96 | 1.719 | 1.272 |
| 48 / 192 | 4.850 | 2.325 |

这组模型每个姿势是单骨骼三维输入，每姿势作用于四个网格输出。300 次姿态更新中，24 姿势的核计算由 7200 次降为 300 次；逐输出核对独立标量结果。耗时包含输入写入和依赖图更新，不包含完整角色蒙皮、IK、渲染；小规模差异及不同机器结果不能换算为通用 FPS。用户提供的基准包中多线程正确性未通过的 native_arrays 方案未采用。

额外回归记录：既有 `tests/test_blender_fbx_mch_local_rotation.py` 在第 263 行查找 `RawArmatureTargets` 的旧约束导出记录时抛出 `StopIteration`。通过仅在独立测试进程中加载 HEAD 版本的 `Exporter/FbxExporter.py`，复现了完全相同的失败；未修改该约束导出分支。本次 BS 专项、真实 sidecar 导出及 Unity v3 数值对齐测试通过。
