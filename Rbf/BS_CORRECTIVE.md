# HoTools BS 修型（Blender 4.5 / HoFBX v3）

## 工作流

骨架对象的数据属性中，`HoTools 修型总览` 与 `HoTools辅助骨总览` 平级。N 面板的 RBF → 修型复用同一绘制函数，并可折叠。

四个原生 UIList 按两行两列排列：左上规则、左下影响物体，右上控制点、右下修型任务。左侧竖排按钮管理列表；规则另有全部启用、全部禁用。下方带框区域编辑当前规则。

1. 添加规则，指定参考骨骼，将需要修型的网格加入影响物体列表。
2. 摆出参考骨骼的局部旋转姿态，点击控制点或任务列表的 `+`。它同时建立一个控制点和对应任务，自动生成不重复的 `_BSC_poseN` 名称。
3. 点击“重置规则”：按影响物体为每个任务建立同名形态键，并生成驱动器。覆盖选项默认开启；关闭后复用已有形态键、保留雕刻数据。重置会重新生成任务的目标映射；自定义多键映射应使用“刷新驱动”保留。
4. 选择点或任务时，另一列表同步定位。点击“预览姿态”仅设置参考骨骼的局部旋转，可直接切到采样姿态编辑修型；“记录当前姿态”更新选中点。
5. 一个任务可手动添加多个网格/形态键目标，也可驱动同一网格上的多个不同键。修改点、半径或目标后，点击“刷新驱动”更新已有键的驱动器，不创建或重置形态键。

基准点始终位于点列表首行，固定为零局部旋转，输出全零；不能编辑、移动、记录覆盖或删除，也不关联修型任务。选择它会清除任务选择。其他点与任务一一对应；在某任务的点上，该任务目标为 1，其他任务目标为 0（含 1e-6 求解正则误差，输出截取到 0..1）。

“重置规则 / 刷新驱动 / 移除驱动 / 删除控件”正常处理活动规则，Shift 点击弹出“处理全部规则”复选框，确认后立即批量执行。“删除控件”删除点、任务和本工具驱动器，保留已有形态键；列表删除任务也会同时删除对应点。新增点需要不同于已有点及零点的局部旋转。

## 驱动与资源

- 仅有 RBF 模式：Gaussian 核、单骨骼局部 XYZ 旋转，界面以度数编辑，RNA/导出以弧度存储。轴角差按 ±π 环绕。这不是多骨骼或 SO(3) 距离求解器；XYZ 奇异姿态仍需按实际姿态采样验证。
- Blender 预览直接读主骨骼 `LOCAL_SPACE`，固定 `rotation_mode=XYZ`；不创建 ADIR、缓存骨或骨骼约束。
- 短表达式调用 `driver_namespace["hotools_bs_rbf"]`，系数存在控制器的 StringProperty。X 输入兼作 `hotoolsBscMarker` 所有权标记，只有三个变换变量，无下划线开头的变量名。
- 一次构造共享核矩阵，一次多右端求解所有任务；求值时按规则和输入值缓存整组输出。小矩阵用纯 Python，大矩阵用 Blender 自带 NumPy，避免每个任务重复 Gaussian 运算。
- 缓存不依赖帧号，同一帧内不同旋转立即重算。刷新替换编译数据并清缓存；加载、撤销、重做恢复已保存的编译数据；移除/清空和卸载释放对应缓存与处理器。
- 刷新及重置先预检整批规则；重复名称、重复点、无效引用、非相对形态键、重复输出和其他驱动器占用会被拒绝。移除根据骨架对象和规则所有权扫描，避免修改目标后遗留旧驱动器；保留其他工具驱动器。
- 工程重开需要 HoTools 已启用及 Blender 允许相应 Python 驱动。算法只由插件提供，不执行工程中任意保存的源代码。

## HoFBX / Unity

v3 元数据显式包含 `influenceObjects`、`tasks[{id,bsName,pointId,targets}]` 和 `rbf.controlPoints[{id,pose}]`。基准固定 `includeBase=true, basePose=[0,0,0]`，不重复导出为作者控制点。Exporter 与控制器共用 schema/version 常量。

导出预处理仍只在需要清除源骨骼 rest 旋转时将测量骨映射为既有 MCH 骨，不创建 ADIR。Unity 中控导入将每个任务目标展开成一条输出规则：所属点权重 1，其余点和零点为 0，保留任务名称、注释和源骨骼信息。来自同一元数据来源的规则可替换重导，手动规则保留。

## 验证

`tests/test_blender_bs_corrective.py` 覆盖原生列表数据操作、点任务同步、固定零点、重置覆盖开关、同网格多键、多网格、外部驱动保护、父级和骨架物体旋转隔离、短表达式、缓存复用/失效、保存重开、批量执行及资源释放。

`tests/benchmark_bs_corrective.py` 对比旧式按任务缓存与整规则缓存的实际依赖图更新。2026-11-17 本机 Blender 4.5.8，8 线程，5×60 次更新取轮均值中位数：

| 作者点 / 输出数 | 旧按任务缓存 ms/update | 整规则缓存 ms/update |
|---|---:|---:|
| 3 / 12 | 0.252 | 0.219 |
| 12 / 48 | 0.673 | 0.556 |
| 24 / 96 | 1.479 | 1.009 |
| 48 / 192 | 4.042 | 2.229 |

这组模型每个点是单骨骼三维输入，每任务四个目标。300 次姿态更新中，24 任务的核计算由 7200 次降为 300 次；逐输出核对独立标量结果。耗时包含输入写入和依赖图更新，不包含完整角色蒙皮、IK、渲染；小规模差异及不同机器结果不能换算为通用 FPS。用户提供的基准包中多线程正确性未通过的 native_arrays 方案未采用。

额外回归记录：既有 `tests/test_blender_fbx_mch_local_rotation.py` 在第 263 行查找 `RawArmatureTargets` 的旧约束导出记录时抛出 `StopIteration`。通过仅在独立测试进程中加载 HEAD 版本的 `Exporter/FbxExporter.py`，复现了完全相同的失败；未修改该约束导出分支。本次 BS 专项、真实 sidecar 导出及 Unity v3 数值对齐测试通过。
