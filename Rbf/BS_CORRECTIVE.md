# HoTools BS 修型（Blender 4.5 / HoFBX v4）

## 工作流

骨架对象的数据属性中，`HoTools 修型总览` 与 `HoTools辅助骨总览` 平级。N 面板的 RBF → 修型复用同一绘制函数，并可折叠；N 面板顶部单独选择要查看的骨架对象，不依赖当前活动对象。

三个原生 UIList 管理规则、影响物体和修型姿势。规则行直接编辑参考骨骼并显示参考骨骼当前局部旋转；列表按钮统一位于右侧，规则另有全部启用、全部禁用。顶部提供范围预览眼睛、重置和刷新操作，姿势列表行显示启用状态、独立影响半径、权重和当前姿态下的 RBF 权重。

1. 添加规则，指定参考骨骼，将需要修型的网格加入影响物体列表。
2. 摆出参考骨骼的局部旋转姿态，点击修型姿势列表的 `+`。它记录当前姿态并自动生成不重复的 `_BSC_poseN` 名称；每个姿势都作用于规则的全部影响物体。
3. 点击姿势行右侧的预览按钮，直接切到该姿态；基准行的按钮回到零旋转。姿势名称和影响半径可以直接在列表行内编辑，骨骼姿态角度只读显示；新增姿态默认影响半径为 30°。
4. 点击“重置规则”：按规则影响物体为每个姿势建立同名形态键，并生成驱动器。覆盖选项默认开启；关闭后复用已有形态键、保留雕刻数据。
5. 修改姿势名称、影响半径或影响物体后，点击“刷新驱动”更新已有键的驱动器；新增形态键或改变规则影响范围时使用“重置规则”。

基准姿势始终位于姿势列表首行，固定为零局部旋转，输出全零；不能编辑、移动、覆盖或删除。其他姿势各自对应一个 RBF 输出通道，在自己的控制点上输出 1，其他姿势和零点输出 0（含 1e-6 求解正则误差，输出截取到 0..1），再乘姿势权重。姿势禁用会同步静音规则影响物体上的对应形态键。

“重置规则 / 刷新驱动”正常处理活动规则，Shift 点击弹出“处理全部规则”复选框，确认后立即批量执行。规则启用开关会同步所有姿势的启用状态；姿势开关会同步对应形态键和驱动器，刷新驱动时会再次校正全部启用状态。刷新按规则和目标逐项尽力执行：缺少形态键、外部驱动或冲突目标只报告警告并跳过该项，其他目标继续完成；重置仍保持全量预检。列表本身负责姿势的删除和清空；重置默认允许覆盖已有同名形态键，关闭覆盖时会保留已有形态键数据。新增姿势需要不同于已有姿势及零点的局部旋转。

## 驱动与资源

- 仅有 RBF 模式：逐控制点局部 Gaussian 核、单骨骼局部 XYZ 旋转；每个姿态控制点独立持有影响半径，新姿态默认 30°，界面以度数编辑，RNA/导出以弧度存储。零值仅作为旧数据的自动半径回退，规则内部半径用于基准点和回退上限，不在界面暴露。轴角差按 ±π 环绕。这不是多骨骼或 SO(3) 距离求解器；XYZ 奇异姿态仍需按实际姿态采样验证。
- Blender 预览直接读主骨骼 `LOCAL_SPACE`，固定 `rotation_mode=XYZ`；不创建 ADIR、缓存骨或骨骼约束。
- 短表达式调用 `driver_namespace["hotools_bs_rbf"]`，系数存在控制器的 StringProperty。X 输入兼作 `hotoolsBscMarker` 所有权标记，只有三个变换变量，无下划线开头的变量名。
- 每个姿势拥有启用开关和 0..1 权重；权重写入 RBF 输出通道，启用状态写入目标形态键和所属驱动器的静音状态。修改权重后点击“刷新驱动”。
- 一次构造共享局部核矩阵，一次多右端求解所有姿势；求值时按规则和输入值缓存整组输出。小矩阵用纯 Python，大矩阵用 Blender 自带 NumPy，避免每个姿势重复 Gaussian 运算。
- 缓存不依赖帧号，同一帧内不同旋转立即重算。刷新替换编译数据并清缓存；加载、撤销、重做恢复已保存的编译数据；移除/清空和卸载释放对应缓存与处理器。
- 刷新及重置先预检整批规则；重复名称、重复点、无效引用、非相对形态键和重复输出会被拒绝。刷新保护其他驱动器；重置勾选覆盖时会替换目标形态键上的已有驱动器。
- 工程重开需要 HoTools 已启用及 Blender 允许相应 Python 驱动。算法只由插件提供，不执行工程中任意保存的源代码。

## HoFBX / Unity

作者数据只保存规则影响物体和姿势；导出边界按“姿势 × 影响物体”临时生成 v4 的 `tasks[{id,bsName,pointId,targets}]`，因此 Unity 侧仍接收明确的输出目标。`rbf.controlPoints[{id,pose,radius}]` 不包含基准点，基准固定 `includeBase=true, basePose=[0,0,0]`。Exporter 与控制器共用 schema/version 常量。

导出预处理仍只在需要清除源骨骼 rest 旋转时将测量骨映射为既有 MCH 骨，不创建 ADIR。Unity 中控导入将每个姿势目标展开成一条输出规则：所属点权重 1，其余点和零点为 0，保留姿势名称和源骨骼信息。来自同一元数据来源的规则可替换重导，手动规则保留。

## 验证

`tests/test_blender_bs_corrective.py` 覆盖原生列表数据操作、姿势名称与固定零点、局部半径、刷新缺键的尽力处理、重置覆盖开关、多网格、外部驱动保护、父级和骨架物体旋转隔离、短表达式、缓存复用/失效、保存重开、批量执行及资源释放。

`tests/benchmark_bs_corrective.py` 对比逐输出缓存与整规则缓存的实际依赖图更新。2026-11-18 本机 Blender 4.5.8，8 线程，5×60 次更新取轮均值中位数：

| 作者点 / 输出数 | 逐输出缓存 ms/update | 整规则缓存 ms/update |
|---|---:|---:|
| 3 / 12 | 0.361 | 0.329 |
| 12 / 48 | 1.004 | 0.933 |
| 24 / 96 | 1.719 | 1.272 |
| 48 / 192 | 4.850 | 2.325 |

这组模型每个姿势是单骨骼三维输入，每姿势作用于四个网格输出。300 次姿态更新中，24 姿势的核计算由 7200 次降为 300 次；逐输出核对独立标量结果。耗时包含输入写入和依赖图更新，不包含完整角色蒙皮、IK、渲染；小规模差异及不同机器结果不能换算为通用 FPS。用户提供的基准包中多线程正确性未通过的 native_arrays 方案未采用。

额外回归记录：既有 `tests/test_blender_fbx_mch_local_rotation.py` 在第 263 行查找 `RawArmatureTargets` 的旧约束导出记录时抛出 `StopIteration`。通过仅在独立测试进程中加载 HEAD 版本的 `Exporter/FbxExporter.py`，复现了完全相同的失败；未修改该约束导出分支。本次 BS 专项、真实 sidecar 导出及 Unity v4 数值对齐测试通过。
