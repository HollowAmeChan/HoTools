# HoTools BS 修型（Blender 4.5 / HoFBX v5）

## 工作流

骨架对象的数据属性中，`HoTools 修型总览` 与 `HoTools辅助骨总览` 平级。N 面板的 RBF → 修型复用同一绘制函数，并可折叠；N 面板顶部单独选择要查看的骨架对象，不依赖当前活动对象。

三个原生 UIList 管理规则、影响物体和修型姿势。规则行直接编辑参考骨骼并显示参考骨骼当前局部旋转；列表按钮统一位于右侧，规则另有全部启用、全部禁用。顶部提供范围预览眼睛、重置和刷新操作，姿势列表行显示启用状态、独立影响半径、权重和当前姿态下的 RBF 权重。

1. 添加规则，指定参考骨骼，将需要修型的网格加入影响物体列表。
2. 摆出参考骨骼的局部旋转姿态，点击修型姿势列表的 `+`。它记录当前姿态并自动生成不重复的 `_BSC_poseN` 名称；每个姿势都作用于规则的全部影响物体。
3. 点击姿势行右侧的预览按钮，直接切到该姿态；基准行的按钮回到零旋转。姿势名称和影响半径可以直接在列表行内编辑，骨骼姿态角度只读显示；新增姿态默认影响半径为 30°。
4. 点击“重置规则”：弹窗列出处理范围内所有已存在的目标键，按相对参考键的顶点差判断是否为空。缺失键自动新建，空键自动重置，非空键默认保留；可以逐键勾选“覆盖”来清空该项修型。确认后所有目标驱动器都会刷新，与是否覆盖顶点数据无关。
5. 半径和权重编辑即时更新已有驱动。修改姿势名称或目标引用后，点击“刷新驱动”更新已有键的连接；需要创建缺失形态键时使用“重置规则”。

姿势行右侧的齿轮打开“高级操作”，其中“改名”会同时修改姿势及规则影响物体上已经存在的对应形态键，保留雕刻数据、相对键关系、动画和驱动连接；缺失键留待重置时创建。操作会先检查全部目标的同名冲突，发现冲突时整项取消，不自动追加 `.001`。列表中直接编辑名称仍只修改目标名称；需要同步改名已有键时使用高级操作。基准姿态没有高级操作入口。

基准姿势始终位于姿势列表首行，固定为零局部旋转，输出全零；不能编辑、移动、覆盖或删除。每个修型姿态独立驱动自己的形态键，在本姿态中心达到设定权重，超过自身半径归零。其他姿态不会改变这条曲线，也不会强迫本键归零；多个修型的形变增量自然叠加，不对总权重归一化。姿势禁用会同步静音规则影响物体上的对应形态键，不把权重重新分配给其他姿态。

“重置规则 / 刷新驱动”正常处理活动规则，Shift 点击弹出“处理全部规则”复选框，确认后立即批量执行。重置弹窗中切换处理范围会重新扫描对应的目标键；空键自动处理，非空键逐项确认，每次打开默认保留已有修型。规则启用开关会同步所有姿势的启用状态；姿势开关会同步对应形态键和驱动器，刷新驱动时会再次校正全部启用状态。刷新按规则和目标逐项尽力执行：缺少形态键、外部驱动或冲突目标只报告警告并跳过该项，其他目标继续完成；重置仍保持全量预检。列表本身负责姿势的删除和清空。新增姿势不能等价于基准零旋转。

## 驱动与资源

- 单骨骼局部旋转，使用单位四元数最短夹角；q/-q 及等价 Euler 表示一致，不受 Euler 分支跳变影响。每个姿态独立持有影响半径，新姿态默认 30°，可编辑范围大于 0°且不超过 180°。Blender 作者数据记录 XYZ 角度供姿态预览，求值还原四元数，导出统一使用 xyzw 四元数和弧度半径。没有规则统一半径、最近邻自动缩窄或姿态间矩阵插值。
- 令 d 为当前旋转到本姿态的夹角，b 为当前旋转到零姿态的夹角，c 为本姿态到零姿态的夹角。`S(t)=clamp01(t)^2*(3-2*clamp01(t))`，最终值为 `weight*S(1-d/radius)*S((b+c-d)/(2*c))`。前项确定有限影响范围，后项固定处理基准归零，不引入用户参数。基准侧可能更早衰减；沿最短旋转路径远离本姿态不会出现全局求解抵消造成的回弹。沿动作路径重新接近本姿态时权重正常回升。
- Blender 预览直接读主骨骼 `LOCAL_SPACE`，固定 `rotation_mode=XYZ`；不创建 ADIR、缓存骨或骨骼约束。
- 短表达式调用 `driver_namespace["hotools_bs_rbf"]`，系数存在控制器的 StringProperty。X 输入兼作 `hotoolsBscMarker` 所有权标记，只有三个变换变量，无下划线开头的变量名。
- 每个姿势拥有启用开关和 0..1 权重；半径和权重编辑自动替换已建立驱动的求值快照并标记依赖图，列表、HUD 与实际形态键同步更新。update 不负责监听骨骼运动，实时旋转仍由原生驱动求值。刷新按钮用于更新连接、目标和启用状态；不创建或清空形态键。规则或总开关禁用时，重置和刷新仍重建驱动并保持静音，再次启用可以立即恢复。
- 预处理与每次求值都是 O(N)，不求逆、不保存矩阵系数。按规则和局部输入缓存整组独立输出，多网格复用结果。
- 视图同时显示当前骨架的全部修型规则，活动规则保持清晰，其他规则的线、点和范围弧降到原不透明度的 18%。每条规则仅对自身选中姿态显示两条摆动弧和一条小扭转弧，所有姿态保留当前权重点标记。活动规则最后绘制，其选中姿态使用独立金色方向线和外圈高亮；其他规则不使用金色高亮。HUD 只显示活动规则选中姿态的偏离角/半径、设定权重与当前输出。缺失参考骨骼的规则单独跳过。范围图是旋转空间的切片，不代表完整三维旋转域；不再将大角度截到 80°，骨骼缩放不扭曲角度弧。
- 缓存不依赖帧号，同一帧内不同旋转立即重算。刷新替换编译数据并清缓存；加载、撤销、重做恢复已保存的编译数据；移除/清空和卸载释放对应缓存与处理器。
- 重置先预检处理范围内全部规则；重复名称、基准等价姿态、无效引用、非相对形态键和重复输出会被拒绝。不同 BS 可以记录同一旋转，输出仍独立。刷新保护其他驱动器；重置会替换所有配置目标上的已有驱动器，保留非空键的顶点数据与驱动刷新互相独立，不影响无关键上的驱动器。空键只接受与相对参考键完全相同的有限坐标；即使当前权重为零或顶点差很小，也不会把已有修型误判为空。
- 工程重开需要 HoTools 已启用及 Blender 允许相应 Python 驱动。算法只由插件提供，不执行工程中任意保存的源代码。

## HoFBX / Unity

作者数据只保存规则影响物体和姿势；导出边界按“姿势 × 影响物体”临时生成 v5 的 `tasks[{id,bsName,pointId,enabled,weight,targets}]`。`rbf.controlPoints[{id,pose,radius}]` 的 pose 是单位 xyzw 四元数，不包含基准点，基准固定 `includeBase=true, basePose=[0,0,0,1]`。契约声明 `evaluation=independent / kernel=smoothstep-compact / distanceMetric=quaternion-angle / neutralMode=triangle-smoothstep`；不兼容旧的高斯矩阵载荷。

HoFBX 导出预处理仍只在需要清除源骨骼 rest 旋转时将测量骨映射为既有 MCH 骨，不创建 ADIR。Unity 导入每个目标为一条独立输出，只持有自己的姿态、半径和权重。导入自动处理 HoFBX Y_X 骨轴的局部四元数符号映射，以及骨骼静止朝向：普通骨读取 `inverse(bind)*local`，MCH 读取 `local*inverse(bind)`，匹配既有 MCH Parent 绑定顺序。参考旋转从原始 FBX prefab 获取，未关联 prefab 时使用导入当时的局部旋转；这些是内部绑定数据，不新增界面参数。同一骨骼的读取和同一姿态的多网格计算共享缓存；父级变换不影响输入。来自同一元数据来源的规则可替换重导，手动规则保留。

## 验证

`tests/test_blender_bs_corrective.py` 覆盖密集姿态 45°/60°/90°在 100°半径下独立叠加、原生驱动实时参数修改、相邻姿态删除与禁用不干扰、姿态范围切片，以及原有列表、逐键重置、父级隔离、保存重开和资源释放。

`tests/test_blender_bs_pose_rename.py` 覆盖多网格及共享数据改名、原生动画和驱动路径跟随、形变保留、启用状态、同名冲突的全量预检、缺失键、弹窗目标绑定和 HoFBX 导出名称。

`tests/test_bs_independent_math.py` 验证固定曲线、基准零值、1000 条随机最短旋转路径的单调衰减、半径增长不降低输出、四元数正负号及 Euler 等价表示。

`tests/benchmark_bs_corrective.py` 对比新独立算法的逐输出缓存与整规则缓存。2026-11-19 本机 Blender 4.5.8，5×60 次更新取轮均值中位数：

| 作者点 / 输出数 | 逐输出缓存 ms/update | 整规则缓存 ms/update |
|---|---:|---:|
| 3 / 12 | 0.355 | 0.359 |
| 12 / 48 | 0.910 | 0.836 |
| 24 / 96 | 1.468 | 1.348 |
| 48 / 192 | 2.609 | 2.277 |

这组模型每个姿态作用于四个网格。300 次更新中，24 姿态的规则入口求值由 7200 次降为 300 次，内部仍分别计算各姿态。耗时包含输入写入和依赖图更新，不包含完整角色蒙皮、IK、渲染；这是同一新算法不同缓存方式的比较，不是新旧数学结果的比较，不能换算为通用 FPS。

Unity 专项包含 Blender 原生驱动的复合旋转样本、跨边界与扭转测试、真实 FBX 静止/目标姿态、HoFBX 用户导出入口及 MCH 预处理检查。测试文件在 Unity 仓库 `Tests~/HoBsCorrective/`。
